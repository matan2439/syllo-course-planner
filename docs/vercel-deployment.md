# Vercel Deployment Guide

## Overview

The project deploys to Vercel as a **zero-config serverless + static** site:

| Path | Served by |
|---|---|
| `/` | `app/web/semester_board_viewer.html` (static, via rewrite) |
| `/app/web/semester_board_viewer.html` | `app/web/semester_board_viewer.html` (static) |
| `/api/board/:programId` | `api/board.ts` (Node.js serverless function, reads from Supabase) |
| `/api/ai/course-planner` | `api/ai/course-planner.ts` (Node.js serverless function, AI streaming) |
| `/data/...` | Static files (local dev only — these are gitignored) |

---

## Required Environment Variables

Set these in the Vercel dashboard before deploying:

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | **Yes** | Supabase pooled connection string (port 6543). Without it, `/api/board/...` returns `503 NO_DATABASE_URL`. |
| `ANTHROPIC_API_KEY` | Yes (for AI) | Anthropic API key. If absent, the AI assistant panel returns a 503 and suggests setting a key. |
| `OPENAI_API_KEY` | Alt for AI | OpenAI fallback if `ANTHROPIC_API_KEY` is not set. |

**`DIRECT_DATABASE_URL` is NOT needed in Vercel.** It is only used locally by `alembic upgrade head`.

### How to add env vars in Vercel dashboard

1. Go to [vercel.com/dashboard](https://vercel.com/dashboard)
2. Open the **tau-course-planner** project
3. Settings → **Environment Variables**
4. Add each variable for **Production**, **Preview**, and **Development** environments
5. Redeploy after adding variables (Vercel does not hot-reload env vars)

## Deployment Steps

### First-time deploy

```bash
# 1. Install Vercel CLI (if not installed)
npm i -g vercel

# 2. Link to project (already done if .vercel/project.json exists)
vercel link

# 3. Add env vars in Vercel dashboard (see above)

# 4. Deploy to production
vercel --prod
```

### Subsequent deploys

Push to the `master` branch — Vercel auto-deploys on every push if connected to GitHub.

Or deploy manually:
```bash
vercel --prod
```

### Preview deployments

Every `git push` to a non-production branch creates a preview deployment at a unique URL like `https://tau-course-planner-abc123.vercel.app`.

## Local Development

### Full stack (API + static files)

```bash
# Requires DATABASE_URL and optionally ANTHROPIC_API_KEY in .env
npx vercel dev
# → http://localhost:3000
```

Board data is loaded from Supabase via `/api/board/mechanical_engineering_2027`.
The browser console logs: `[board] source: api | program: ... | repo: 56`

### Static fallback (no database needed)

```bash
python -m http.server 8080
# → http://localhost:8080/app/web/semester_board_viewer.html
```

Board data is loaded from `data/parsed_json/mechanical_semester_board_2027.json`.
The browser console logs: `[board] source: static-json | program: ... | repo: 56`

Note: the AI assistant and board API endpoint are not available in this mode.

## How the board API works

`GET /api/board/mechanical_engineering_2027`

1. Parses `programId` → `{ base: "mechanical_engineering", year: 2027 }`
2. Queries Supabase: `SELECT board_json FROM program_versions WHERE program_id = $1 AND academic_year = $2`
3. Returns the 161 KB pre-computed board JSON as-is

The board JSON was seeded into Supabase by:
```bash
python -m app.pipeline.seed_postgres
```

To refresh the board data after a pipeline update:
```bash
python -m app.pipeline.generate_2027_board   # regenerates board JSON
python -m app.pipeline.seed_postgres         # re-seeds to Supabase
```

## Database migrations

Alembic migrations run **locally** against the direct Supabase connection, not through Vercel:

```bash
# Apply pending migrations
DIRECT_DATABASE_URL=postgresql://... alembic upgrade head

# Check current revision
DIRECT_DATABASE_URL=postgresql://... alembic current
```

## Known Limitations

1. **Static JSON not in cloud** — `data/parsed_json/` is gitignored and not deployed to Vercel. The static fallback only works locally. In cloud, `DATABASE_URL` must be set.

2. **Board data is pre-computed** — The board JSON is a snapshot generated by the Python pipeline. It is not rebuilt automatically on deploy. Run `seed_postgres.py` after any pipeline update.

3. **Python pipeline is local-only** — All data ingestion (TAU IMS scraping, Arazim grade import, board generation) runs locally. There is no automated cloud pipeline yet.

4. **Single program supported** — Only `mechanical_engineering_2027` has board data in Postgres. The 2025 programs fall back to gitignored static JSON and will not load in cloud.

5. **AI assistant is advisory** — Responses are based on local board data only. The AI never queries Supabase directly.

6. **Alembic on Windows** — `DIRECT_DATABASE_URL` must be exported in the shell before running `alembic`; it is not read from `.env` by default in some shells.

## Vercel configuration reference (`vercel.json`)

```json
{
  "version": 2,
  "framework": null,
  "rewrites": [
    { "source": "/api/board/:programId", "destination": "/api/board?programId=:programId" },
    { "source": "/",                     "destination": "/app/web/semester_board_viewer.html" }
  ],
  "headers": [
    {
      "source": "/api/(.*)",
      "headers": [
        { "key": "Access-Control-Allow-Origin",  "value": "*" },
        { "key": "Access-Control-Allow-Methods", "value": "GET, POST, OPTIONS" },
        { "key": "Access-Control-Allow-Headers", "value": "Content-Type" }
      ]
    }
  ]
}
```

`"framework": null` is required to prevent Vercel from auto-detecting the Python pipeline (`app/main.py` + `requirements.txt`) as a FastAPI application, which would crash on Windows due to a Vercel CLI path-escaping bug.
