## Commands (scripts/degree.py)

One argparse parser for all subcommands (`<cmd> --help` prints the same full help).

| Command | Network | Writes |
| --- | --- | --- |
| `init --institution tau --title-he .. --level .. --school .. --shana .. --name-en .. [--base ..] [--track-he ..]` | always (index search + `evidence --live`) | registry entry (draft), spec skeleton, evidence.json |
| `evidence --program <id> [--live\|--offline]` | per flag | evidence.json; prints counts by kind |
| `todo --program <id> [--reuse-from <other-id>] [--apply-suggestions]` | never (reads evidence.json) | todo.md; `--reuse-from` (first) copies the other degree's entries for identical evidence, `--apply-suggestions` writes suggested coverage, both into spec.json. Exit 0 iff nothing open and no stale keys. |
| `refresh --program <id> [--live\|--offline] [--apply]` | per flag | facts snapshot + review report; `--apply` then builds into `data/` |
| `build --program <id> [--live\|--offline] [--out-dir DIR]` | per flag (none = caches, fetch missing) | the four board files (into DIR with `--out-dir`) |
| `check --program <id> --live\|--offline` | per flag (a flag is required) | the check report; exit 0 only if all pass |
| `publish --program <id>` | always (`--offline` is refused) | build into `data/`, then on all-PASS: registry status `live` + RELEASE.md |

- `--live` and `--offline` are mutually exclusive.
- `--program` must be a bare id: `<inst>:`-prefixed ids validate in the registry but
  degree.py refuses them ("prefixed ids need a filesystem slug — not supported yet").
- `check` runs: coverage, freshness (live only; SKIPPED offline, so offline never passes),
  courses_known, double_counting, mandatory_offered, degree_length, totals,
  board_carries_requirements, plannable (board audit errors), rules_enforced, known_gaps.
  Problems prefixed `warn:` never fail a check.
- `board_carries_requirements`: every spec requirement must reach the board (what
  `spec_to_program` emits, read the way the builder reads categories). One problem per
  requirement that cannot:
  - a `group_minimums` entry other than `core` (only `core` becomes `core_courses_total_min`;
    EE's `{"track": 12}` fails);
  - a category that never reaches the board's category list: shadowed (keyed as
    `requirements.<key>` while `elective_categories` takes precedence), keyed under a key the
    reader does not read, or unkeyed in a non-core group with no plain category beside it;
  - any category `min_credits` (the board enforces `min_courses` only);
  - `general_requirement.credits_required` != `min_courses` x `institutions.json`
    `generalRequirement.creditsPerCourse` (or not verifiable).
  It means "the board can't carry this yet". Report it to the owner like `rules_enforced`;
  never delete or weaken the requirement to pass.
- `publish` refuses an already-`live` degree (`--update` = Plan 3, not built, exit 1), refuses
  `--offline`, and on any FAIL/SKIP exits 1 with the registry unchanged (built files stay in
  the working tree — review or discard them). On success it prints, never runs:
  `ENV_FILE=.env.local node scripts/update-board-json.mjs <base> <year> data/boards/<id>.json`
  and "commit, open a PR, deploy". For a never-seeded degree that sync updates 0 rows (no
  `program_versions` row yet); the committed board is what the API serves after the deploy.
- Drafts are never served by the API; only `live` degrees are.

## Evidence id scheme (TAU)

`T = tau:<tcid>:<shana>`. Text-derived ids end in `text_id` = first 12 hex chars of sha1 of
the whitespace-collapsed, HTML-stripped text, so changed official text = a new id (the old key
turns stale).

| id | kind | source |
| --- | --- | --- |
| `T:body:teurtochnit` / `teurtoar` / `teurshaot` / `disclaimerletoar` | program_text | program page body |
| `T:body:hesbernosaf:<sha12>` | rule_text | program-wide extra explanation |
| `T:body:terms:<sha12>` | policy_text | linked documents (terms, regulations, previous booklets) |
| `T:rama:<ramaid>` | section | a section of the program tree (title, hours, weight) |
| `T:rama:<ramaid>:hesber:<sha12>` | rule_text | a section's explanation |
| `T:rama:<ramaid>:kurs:<kursshow>` | course_listing | a course listed in a section (`cancelled` when mevutal=1) |
| `T:rama:<ramaid>:kurs:<kursshow>:hearakurs:<sha12>` / `:idkunkurs:<sha12>` | rule_text | a course note / dated update; a "קורס ליבה (ב)מסלול X" note carries `data.core_of_track` (list of the track names it names, verbatim, typos kept) |
| `T:timetable:<course>` | course_fact | program timetable (ydmaarechet); `data.semesters` |
| `tau:ims:<shana>:<course>` | course_fact | IMS course search (course-wide) |

Program page items' `source_url` is `https://tochniot.tau.ac.il/graphql`; the timetable's is
`https://www.tau.ac.il/study-program?safa=1&shana=<shana>&tab=schedule&tcid=<tcid>`.
The same course in two sections gives two listing ids (and two note ids).

Regulations PDFs (`tau_pdf`): `pdf:<doc>:<sha12>` (rule_text, one per sentence or heading;
`<doc>` = first 12 hex of sha1 of the PDF URL) and `pdf:<doc>:unread-page-<n>` (a page with no
text layer, `data.unread`; `coverage` fails unless it is `mapped_to: known_gaps[...]`).
TAU engineering's Terms_BA.pdf is `pdf:b6a7c762f8db:*` (364 sentence items), fully mapped in
`mechanical_engineering_2027`: an engineering degree reuses it with `todo --reuse-from
mechanical_engineering_2027` (see "Reusing another degree's coverage" below); retire an
`unread-regulations-pdf` known gap only once every item of that document is mapped.

## Spec paths (`resolve_spec_path`)

A `mapped_to` value must be one of:

- `total_required_credits`, `general_requirement`, `catalog_year_policy`, `degree_years`
- `mandatory_courses[<course_id>]`
- `categories[<category_id>]`
- `categories[<category_id>].course_ids[<course_id>]`
- `group_minimums.<group>`
- `course_rules[<rule_id>]`
- `known_gaps[<gap_id>]`

Course ids are dashed (`0542-3792`). Anything else, or a target missing from the spec, is an
"unresolved mapping".

`mapped_to` may also be a list of these paths, when one item states several rules (a PDF
sentence giving both the pass and the fail grade; a hesber with the total and the English
rule): `{"mapped_to": ["total_required_credits", "course_rules[english-two-courses]"]}`. Every
target must resolve; `todo` prints the targets and names the unresolved ones. An unread-page
item's list may hold only `known_gaps[...]` targets.

## DegreeSpec fields

`program_id`, `institution`, `source_year`, `total_required_credits`, `degree_years` (3..6,
default 4; spec-only: the early board is Years 1-2, the program board Years 3..N),
`catalog_year_policy`, `mandatory_courses` (`course_id`, `year`, `semester` A/B/either, `placement_rule`),
`categories` (`category_id`, `name_he`, `min_courses`, `min_credits`, `course_ids`, `group`),
`group_minimums` (`{"core": 6}`), `general_requirement` (free dict: `category_id`,
`min_courses`, `credits_required`, `course_ids`, ...; `credits_required` is spec-only),
`double_counting` (`forbidden` | `allowed_listed`) + `allowed_double_counted`, `ui`, `legacy`
(ME migration only; a new degree leaves it `{}`), `coverage`, `source_conflicts`
(`course_id` or null, `description`, `sources`), `course_rules`, `known_gaps`.
All models forbid unknown keys.

- `course_rules[].kind`: `equivalent_to`, `prerequisite_substitute`, `year_restriction`,
  `cohort_restriction`, `offering_window`, `annual`, `general_requirement_exemption`,
  `distinct_categories` ("N courses from K different categories"; params `min_courses`,
  `min_distinct_categories`, `category_members` {category_id: [course ids]} — keys must be spec
  categories and `course_ids` must equal the union of the members), `mutually_exclusive` (the
  source says the courses overlap and cannot both be taken), `language_requirement` (a
  degree-wide language-of-instruction requirement, e.g. N courses in English), `load_limit`
  (bounds on a semester's load, e.g. under 75% needs approval, at most N graduate courses),
  `study_duration` (standard length / extension of the degree; `params.semesters` /
  `params.years`, when present, must equal `degree_years` * 2 / `degree_years`, else
  `degree_length` fails — even with the disagreement recorded in `source_conflicts`: it stays
  red, naming the rule and the conflict, until the owner rules which source governs; a
  non-whole length such as 9 semesters / 4.5 years cannot be expressed by `degree_years` yet), `prerequisite_policy` (how
  prerequisites are read degree-wide, e.g. "before or in parallel").
  `enforced_by: "board"` only with the board field cited in `note`; `"none"` fails
  `rules_enforced` until the planner enforces it.
- `known_gaps[]`: `gap_id`, `description`, `source_ids`. Fails `known_gaps` while present;
  closed by reading the source and mapping what it says.
- Suggestions (`todo --apply-suggestions`) cover (cancelled items never):
  - course_listing / course_fact items whose course has exactly one home -> that home;
  - a multi-home course's listing -> the one category holding it whose `name_he` equals the
    section it is listed under: the LAST path element, or a repeated section's `also_at`
    location (HTML-stripped). None or several -> by hand. Limitation: only the last element is
    compared, so "מעבדה מתקדמת מסלול X" listed under "מעבדות מתקדמות" gets nothing;
  - a multi-home course's fact -> `mandatory_courses[<id>]` if mandatory, else the list of all
    its homes;
  - a course note with `data.core_of_track` -> `course_rules[<rule>]` when exactly one
    `distinct_categories` rule lists the course;
  - section items whose `ramaid` maps to one category through `legacy` (ME only).
  Everything else is mapped by hand.

## Reusing another degree's coverage (`todo --reuse-from`)

Runs before suggestions. For each evidence id present in both degrees with identical
`raw_text`, mapped there and not yet covered here: a `not_planning_rule` copies as-is; a
`mapped_to` copies only when every target resolves in this spec, else it lands under "needs
review" (not written). A course item (`course_listing` / `course_fact`) of a course this spec
places always lands under "needs review" — suggestions own it. Ids whose text differs are
skipped and counted. Every copied entry is listed under "reused from <other> (verify)": read
each one; a copy is a starting point, not a review.

Dry run, EE <- ME (2026-11-05, `electrical_engineering_2027` draft rebased onto the tools):
of EE's 364 Terms_BA.pdf items, 348 copied (346 not-a-rule + 2 `catalog_year_policy`), 16
needs review (ME's `course_rules`: duration, extension, load, graduate-course cap,
prerequisite semantics, year progression, reserve-duty prerequisites — EE writes its own). To
fix in the copies: `pdf:b6a7c762f8db:054faa375f0f`'s reason names ME's program page
(`tau:8715:...`); the duration sentence `4c0e7bbf7f85` lists the 9-semester programs, and EE
is not among them (8 semesters, matching `degree_years` 4).

## TAU conventions

- **Year code**: `shana` = the calendar year the academic year starts (2026 = 2026-2027 =
  תשפ"ז). Registry `year` = `sourceYear + 1` (id `<base>_<shana+1>`, e.g.
  `mechanical_engineering_2027`).
- **Program index** (`init`): query `{"safa":"1","freeSearch":<title>}`, relevance-ranked, only
  the first 100 results are read, and it serves only the CURRENT catalog year (init cannot
  scaffold a past year). `toar` is a Hebrew label: `ראשון` (bachelor) / `שני` (master);
  `--level` accepts aliases `1` / `2`. A program with an empty `betsefer` matches on its `chug`.
  The index has no English title, so `init` requires `--name-en`.
- **Timetable `semkvutza`**: last digit = `0` annual (A+B), `1` semester A, `2` semester B.
- **Empty legal-semester list = unknown**, not "never offered" (a course IMS lists as not
  offered gets `offered_in_year: false` instead).
- **`hearakurs` / `idkunkurs`** are lists of dicts (a note per entry), each its own rule_text item.
- **Facts file** `data/official/tau_course_facts_<shana>.json` is per year; program-scoped parts
  (ydtochnit row, timetable, offering) live under `programs[<tcid>]`, IMS is course-wide.
- A refresh that read both the program page and the timetable drops courses TAU removed.

## curation.json (optional overlay)

A JSON list; each entry overrides one board value after the build:

```json
{"board": ["semester_board", "board"], "course_id": "0542-3792", "field": "placement",
 "value": {"year_3_semester_a": 5, "year_3_semester_b": 0},
 "built": {"year_3_semester_b": 2}, "retire": null, "reason": "<why, citing the source>"}
```

`board` names any of `semester_board`, `board`, `early_years`; `built` is the value the builder
produced when the entry was written (omit it when the builder produced no such field). The
build fails (`StaleCurationError`) if the target is gone, if the build now produces `value`
itself, or if it produces anything other than `built` — review, then update `built` or retire
the entry. A new degree normally has no curation.json (it builds from spec + facts).

## New year of an existing degree

`init` gives every new entry `familyId = base` and `isFamilyDefault: true`, and the registry
allows exactly one default per family, so a new year of an existing family is refused
("the registry would be invalid: every family needs exactly one isFamilyDefault entry"). Promoting
a new year needs an atomic flip of both entries' `isFamilyDefault` / `status` in
`programs.json` — a code/registry change for the owner, not something to hack around with a new
`--base`.

## Worked example: Mechanical Engineering 2027

`mechanical_engineering_2027`, tcid 8715, shana 2026, `data/degrees/tau/mechanical_engineering/2027/`.

- Evidence: 948 items — course_fact 195 (87 timetable + 108 IMS), course_listing 179,
  rule_text 530 (166 program page + 364 sentences of the regulations PDF `pdf:b6a7c762f8db:*`),
  section 30, policy_text 11, program_text 3.
- Coverage: 948 entries = 330 auto-suggested / 121 hand-mapped / 29 to course_rules /
  468 `not_planning_rule`. The 330 suggestions are all course items (0 sections). Hand-mapped
  121 = categories 97 + mandatory_courses 14 + general_requirement 4 + group_minimums 3 +
  catalog_year_policy 2 + total_required_credits 1. The regulations PDF (Terms_BA.pdf, 364
  sentence items): 16 to course_rules, 2 to catalog_year_policy, 346 not-a-rule (grading,
  exams, appeals, status, accommodations, procedures; 58 headings).
- course_rules: 14 — two enforced by the boards (`annual-0542-3792`, note cites
  `is_annual=true, spans_semesters=[...], count_hours_once=true`; `duration-8-semesters`, note
  cites both boards' `semester_id`s), 12 `enforced_by: "none"` (6 from the program page, 6
  degree-wide from the regulations: load, extension, prerequisite semantics, year progression,
  graduate-course cap).
- known_gaps: none. `unread-regulations-pdf` (the PDF linked from `T:body:terms:8026588cd798`)
  was retired by reading the PDF with the `tau_pdf` adapter and mapping every item.
- source_conflicts: 10 recorded, not applied (e.g. total credits 185 in the spec vs. 184 /
  185.5 on the program page; 0542-2500 listed in both Y2/B and Y3/A).
- curation.json: 802 entries — 768 tagged `retire: "post_migration"` (to retire with the first
  real update) and 34 `retire: null` (durable hand corrections, e.g. the 0542-3792 annual lab:
  `is_annual`, `spans_semesters`, `placement`). The ME boards are plannable only with it: a
  clone of the spec without it fails `plannable` (`annual_not_represented: 0542-3792`).
- Current state (as of 2026-11-04): `check --live` red only on `rules_enforced` (the 12
  rules) — the same red a new degree should expect. It is `live`
  (pre-pipeline), so `publish` refuses it; `degree_length` passes (`degree_years` 4 by default; mandatory
  years 1-4; `duration-8-semesters` says 8 semesters / 4 years).
- general_requirement: 88 שער רוח `course_ids`, migrated from the legacy program
  (`data/programs/mechanical_engineering_2027_enriched.json`) and identical, in order, to
  `data/general_courses_shaar_ruach.json` `courses[]` — the file a new TAU degree copies them
  from. `min_courses` 3 / `credits_required` 6 come from ME's own program text.
